# 开发笔记

## 环境

入口是项目根目录的 `main.py`。Python 3.11–3.12，PySide6 固定为 6.8.3；本机使用较新的 Qt 版本时遇到过 DLL 加载问题，因此暂时保留这个版本。安装依赖使用 pyproject.toml，锁定版本见 requirements-lock.txt。

`.venv` 是本地环境，不随源码迁移。几何、文档和样本库模块独立于 Qt，界面负责操作和显示。

## 数据约定

- 坐标统一为 nm，Y 轴向上。GDS 写入精度为 0.1 nm。
- Pattern key、Shape.id 和工程版本是持久化标识，调整协议时需要考虑已有工程。
- 一个 Shape 可以通过 `entries()` 生成多个图层，Layer 和 Datatype 都需要保留。
- `metadata.calibrated=False` 表示未标定。改变整体缩放只改变坐标，不会自动变成已标定样本。
- 导出 manifest 中的对象记录与 GDS Cell 对应，检测工具可以据此查找参数和来源。

## 样本库

`library.py` 管理 SQLite；`matching.py` 负责几何指纹和近似轮廓比对；`layout_source.py` 读取 KLayout 层级数据库；`jobs.py` 是后台进程入口；`dataset.py` 负责数据集导出。界面通过 `add_library_shapes()` 把样本送入编辑器。

默认提取 Cell 定义，避免展开重复阵列。递归提取按实例的实际位置遍历，可以配合 ROI。图库每页 80 个样本，单批默认上限为 20000 个几何和 10000 个样本；超限或取消会撤回未提交的事务。

每个进程独立创建数据库连接和 Layout 对象。进度通过队列传递，几何直接写入样本库。SQLite 使用 WAL，提取期间仍能浏览已有样本。

文字备注从独立 Cell 定义中收集，每个 Cell/层最多 200 条，坐标是定义中的局部坐标。它们没有按阵列实例展开，也没有按 ROI 精确筛选。需要精确定位标注时，可以增加独立文本索引。

## 编辑器

画布最多导入 50000 个多边形，文件达到 20 MiB 时转到样本库后台索引。Undo 使用完整文档快照，最多 80 条；scene 按对象 ID 复用图元，只重建变化的几何。大工程的历史存储和对象列表刷新还有优化空间。

导出采用对象 Cell 加 TOP 引用，复制阵列暂时没有压缩为 AREF。隐藏图层也会导出，显示和锁定是编辑状态。参数化 Via、Cut、Active 结构的辅助层默认使用主 Layer+1，可展开后重新分层。

图片导入使用阈值轮廓。SEM 纹理、同色标注和遮挡需要裁剪或人工修正；颜色分层和分割模型可以作为独立 provider 接入现有标定、孔洞处理和预览流程。

## 构建与检查

运行 `python -m pytest -q` 检查几何和界面流程；修改 GDS 输出后，再核对单位、图层和孔洞。Qt 的对象生命周期、剪贴板释放和后台取消也需要注意。

KLayout 是运行依赖，当前使用的 wheel 采用 GPL-3.0-or-later。构建脚本附带分发许可、自有源码和上游源码归档，同时备份旧桌面目录中的 userdata、examples 和 user_plugins。

## 后续方向

多层联合样本、实例来源定位和增量索引可以在样本库侧扩展。大量编辑对象适合改用增量撤销命令，并增加 Cell/AREF 复用。检测程序的单位、图层、TOP Cell 和样本命名约定确定后，可以在导出模块增加配置。
